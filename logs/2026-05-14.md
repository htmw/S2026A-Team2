## Download CSV Returning Raw Data (frontend/app_t3.py)

**Bug:** Downloading the transformed dataset after a pipeline run returned the original unmodified CSV — renames, filters, and drops were all absent from the downloaded file.

**Root cause:** `st.session_state.transformed_df` is set once on Transform page load via `run_transform(uploaded_dfs)` (raw data). The SSE `node_done` handler for `engineer_execute` captured the verdict and error from the event but never read `transformed_data` from it and never updated `transformed_df`. The download button always served the stale page-load value.

The backend was correctly sending `transformed_data` in the `engineer_execute` node_done event — the data was there, the frontend just wasn't consuming it.

**Fix:** Added two lines to the `engineer_execute` node_done handler in `app_t3.py`:

```python
td = event.get("transformed_data")
if td:
    st.session_state.transformed_df = pd.DataFrame(td)
```

This overwrites `transformed_df` with the pipeline output as soon as engineer_execute completes, so all subsequent download buttons serve the correct transformed data.

## Engineer Agent — Wrong Filter Direction (agents/engineer.py)

**Bug:** The Engineer consistently generated `df[condition]` (keep matches) when the instruction said "Drop rows where X" — it should have generated `df[~condition]` (remove matches).

**Example instruction:** "Drop all rows where English is not in the course title"  
**Wrong output:**
```python
df = df[df['course_title'].str.contains('English', case=False, na=False)]
```
**Correct output:**
```python
df = df[~df['course_title'].str.contains('English', case=False, na=False)]
```

**Root cause:** The Engineer's system prompt had this line:
> "If the plan contains a 'Filter rows' step, implement it as a row-selection filter. The result must contain ONLY the matching rows."

This actively taught the model to always keep matching rows, regardless of whether the instruction said "drop" or "keep". The model was ignoring the direction of the filter.

**Fix:** Replaced the ambiguous rule with an explicit one distinguishing "Drop" from "Keep":
```
- CRITICAL: Read "Drop rows where X" as REMOVING those rows — use df = df[~condition].
  Read "Keep rows where X" as KEEPING only those rows — use df = df[condition].
  Never confuse these two directions.
```
