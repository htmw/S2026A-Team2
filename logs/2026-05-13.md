## CUDA Profiler Node (explored, then removed)

Explored adding a GPU-accelerated data profiling node between Scout and Architect. The idea was to compute per-column statistics (null count, min/max/mean, unique count) using Numba CUDA kernels in parallel, giving the Architect LLM richer data context before planning transformations.

Built and wired in:
- `agents/profiler.py` — Numba CUDA kernels with shared-memory block reduction, CPU fallback via NumPy, 100k row threshold to decide GPU vs CPU path
- `frontend/test_profiler_app.py` — standalone Streamlit demo app
- Parquet support in Scout, `data_profile` field in ETLState, profiler wired into all graph variants

**Why it was removed:** The GPU is on a remote tower (gaami) accessed via Tailscale. The demo is presented from a laptop browser. In that setup the CUDA work is invisible to the audience and adds an unnecessary layer of abstraction. pandas `df.describe()` does the same thing in one line. The Ollama LLM pipeline is the real demo value — the profiler was overkill for what it actually added.

All profiler code was reverted. Pipeline is back to `Scout → Architect → Engineer (generate) → Engineer (execute) → Loader`.

## Remote Demo Setup (gaami + Tailscale)

Established the remote demo architecture:
- Streamlit + Flask backend + Ollama models all run on gaami
